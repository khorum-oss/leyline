# Open questions

Each of these gets resolved during specification and planning, and the decision
gets recorded in `decisions/` with a link back here. The suggested starting
point carries no authority beyond being a reasonable default to argue against.

| ID  | Question                                                                                                                                   | Suggested starting point                                                                                                                              | Decide by |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- | --------- |
| OQ1 | **Persistence of applied changes.** Should an agent's renderer swap survive a page reload?                                                 | Ephemeral by default, with an explicit export-to-file operation, so source control stays the durable record                                           | Stage 2   |
| OQ2 | **Granularity of policy.** Per-operation, per-target-type, per-initiator, or a combination                                                 | A single predicate receiving the whole proposal and initiator, plus helper combinators                                                                | Stage 2   |
| OQ3 | **Renderer identity across bundles.** How a renderer advertises itself for discovery — name, description, which surface types it can claim | A small registration metadata contract, required for a renderer to become addressable at all (I3 depends on this)                                     | Stage 3   |
| OQ4 | **Confirmation flow.** Who confirms when policy returns "require confirmation", and how                                                    | An application-supplied callback; the MCP adapter surfaces it as a pending state                                                                      | Stage 4   |
| OQ5 | **Minimum surface set for v1**                                                                                                             | `form`, `datatable`, `metric-panel`, `link`, `text` — nothing beyond what brief §2 needs                                                              | Stage 1   |
| OQ6 | **Trace retention and export.** Whether the ring buffer offers a built-in JSON export                                                      | A minimal `export()` on the ring buffer, for bug reports and replay elsewhere                                                                         | Stage 2   |
| OQ7 | **Initiator identity and trust.** Whether Leyline carries an authenticated identity from the transport, or treats the label as advisory    | Advisory in v1; the policy hook documented as the place to enforce anything stronger, with the trace stream recording whatever the transport provides | Stage 4   |
| OQ8 | **Guard evaluation event volume.** Individually, batched per snapshot, or gated behind a verbosity level                                   | A per-kind enable set on the emitter, so guard events can go quiet without losing transitions and control-plane events                                | Stage 2   |
